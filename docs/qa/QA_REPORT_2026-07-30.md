## QA에서 수정한 결함

1. 단축키 버튼이 새 문서 `+` 옆에 있어 탭 기능처럼 보였다. 제목 표시줄의 테마·언어 옆 전역 도구 영역으로 옮겼다.
2. 이미지 라이트박스 위에서 `Ctrl+/`를 누르면 단축키 모달이 뒤에 열릴 수 있었다. 단축키 모달을 열기 전에 라이트박스를 닫도록 했다.
3. 업데이트 팝업 내부에서 단축키 모달을 열면 닫을 때 숨겨진 버튼으로 포커스가 복귀할 수 있었다. 임시 UI에서 시작한 포커스는 가시적인 단축키 버튼으로 복귀시킨다.
4. 단축키 모달이 열린 동안 `Ctrl+N` 같은 배경 명령이 실행될 수 있었다. 모달 입력을 분리하고 회귀 테스트로 고정했다.

## 효율화한 검증 흐름

검증을 소스 게이트, 변경 영역 E2E, 릴리스 패키지 게이트, 상태 변경 전체 회귀로 계층화했다. 이번 릴리스에서는 최종 패키지를 한 번 확정한 뒤 그 산출물을 WebView·패키지·배포판 실행 검증에 재사용했다.

업데이터, 설치 제거, 파일 연결 코드는 변경하지 않았으므로 합성 다음 버전을 다시 만들고 로컬 설치를 여러 번 교체하는 `PortableUpdateE2E`, `InstallerUpdateE2E`, `InstallerLifecycleE2E` 전체 회귀는 실행하지 않았다. 해당 경로는 업데이트·설치 코드 변경 또는 정기 전체 회귀에서 수행한다. 패키지의 업데이트 입력 방어와 실제 설치·실행은 이번 게이트에 남겨 신뢰 경계를 유지했다.

## 실행한 핵심 검증

```powershell
.\tests\RepositoryContracts.ps1
node --check .\src\web\app.js
node --check .\src\web\i18n.js
.\scripts\build-release.ps1
.\tests\WebViewBehaviorE2E.ps1 -AppPath .\artifacts\publish\MarkDownEditor.exe
dotnet run --project .\tests\UpdateValidation\UpdateValidation.csproj -c Release -- `
  .\artifacts\MarkDownEditor-standalone.zip `
  .\artifacts\MarkDownEditor-standalone `
  .\artifacts\MarkDownEditor-Setup-x64.exe
.\tests\FileOpenE2E.ps1 -AppPath <portable-exe> -Edition portable
.\tests\FileOpenE2E.ps1 -AppPath <installed-exe> -Edition installed
```

모든 최종 명령은 종료 코드 0이었다. 실제 화면은 1440×900 다크 테마에서 최종 제목 표시줄 버튼 배치와 스크롤 가능한 중앙 단축키 모달을 확인했다.

## 남은 위험

바이너리에는 Authenticode 서명이 없어 Windows SmartScreen 경고가 표시될 수 있다. 릴리스 체크섬과 manifest, 앱의 GitHub asset digest·파일 버전 검증은 유지한다.

전체 설치 제거·자동 업데이트 성공 경로는 이번 변경 범위에서 재실행하지 않았다. 업데이트 또는 설치 관련 회귀가 의심되면 상태 변경 전체 게이트를 추가 실행해야 한다.
